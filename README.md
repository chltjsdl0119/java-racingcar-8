## 과제 진행 요구 사항 체크

- [x] 자동차 경주 저장소 포크 및 클론
- [x] 구현할 기능 목록 정리

## 기능 목록

### 1. 입력
- [ ] camp.nextstep.edu.missionutils.Console의 readLine()을 통해 경주할 자동차 이름을 입력받는다.
- [ ] 자동차 이름은 쉼표(,) 기준으로 구분한다.
- [ ] 자동차 이름은 5자 이하로만 입력 가능하다.

- [ ] 시도할 횟수를 입력받는다.
- [ ] 숫자가 아닌 경우와 1 이하의 숫자인 경우 IllegalArgumentException을 발생시킨다.

### 2. 자동차 생성
- [ ] 입력받은 이름으로 자동차를 생성한다.
- [ ] 자동차는 이름과 현재 거리를 가진다.

### 3. 전진 조건 판단
- [ ] camp.nextstep.edu.missionutils.Randoms의 pickNumberInRange()를 통해 0~9 사이의 숫자를 무작위로 추출한다.
- [ ] 4 이상이면 전진한다.
- [ ] 3 이하라면 멈춘다.

### 4. 경주 시작
- [ ] 사용자가 입력한 시도 횟수만큼 경주를 반복한다.
- [ ] 각 시도 결과를 출력 형식에 맞게 출력한다.

### 5. 우승자 판단
- [ ] 가장 멀리 이동한 자동차의 위치를 구한다.
- [ ] 동일한 최대 거리를 가진 자동차가 존재할 경우, 공동 우승 처리한다.

### 6. 출력
- [ ] 최종 우승자를 출력한다.(예: 최종 우승자 : pobi, jun)

## 프로그램 구조

### InputView
- 입력의 책임을 가진다.

### OutputView
- 출력의 책임을 가진다.

### RacingController
- 게임 전체 진행의 책임을 가진다.

### MoveStrategy
- 전진 전략 인터페이스.

### RandomMoveStrategy
- 랜덤 전진 전략 책임을 가진다.

## 프로그래밍 요구 사항
- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
- 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- 3항 연산자를 쓰지 않는다.
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
