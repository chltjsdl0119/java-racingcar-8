# java-racingcar-precourse

## 과제 진행 요구 사항 체크

- [x] 자동차 경주 저장소 포크 및 클론
- [x] 구현할 기능 목록 정리

## 기능 목록

### 1. 입력
- [x] camp.nextstep.edu.missionutils.Console의 readLine()을 통해 경주할 자동차 이름을 입력받는다.
- [x] 자동차 이름은 쉼표(,) 기준으로 구분한다.
- [x] 시도할 횟수를 입력받는다.

- [x] 숫자가 아닌 경우 IllegalArgumentException을 발생시킨다.
- [x] 1 이하의 숫자인 경우 IllegalArgumentException을 발생시킨다.

 ### 2. 자동차 생성
- [x] 입력받은 이름으로 자동차를 생성한다.
- [x] 자동차 이름은 1자 이상 5자 이하여야 한다.
- [x] 자동차는 이름과 현재 거리를 가진다.

### 3. 전진 조건 판단
- [x] camp.nextstep.edu.missionutils.Randoms의 pickNumberInRange()를 통해 0~9 사이의 숫자를 무작위로 추출한다.
- [x] 4 이상이면 전진한다.
- [x] 3 이하라면 멈춘다.

### 4. 경주 시작
- [x] 사용자가 입력한 시도 횟수만큼 경주를 반복한다.

### 5. 우승자 판단
- [x] 가장 멀리 이동한 자동차의 위치를 구한다.
- [x] 동일한 최대 거리를 가진 자동차가 존재할 경우, 공동 우승 처리한다.

### 6. 출력
- [x] 각 시도 결과를 출력 형식에 맞게 출력한다.
- [x] 최종 우승자를 출력한다.(예: 최종 우승자 : pobi, jun)

## 프로그램 구조

### View 계층
- InputView
  - 사용자 입력을 처리하는 책임.

- OutputView
  - 게임 진행 상황과 최종 결과를 출력하는 책임.

### Controller 계층
- RacingController
  - 게임의 전체 흐름을 관리한다.

### Domain 계층
- Car
  - 단일 자동차의 상태(이름, 위치)를 관리한다.

- Cars
  - 자동차 전체를 관리한다.

- RacingGame
  - 전체 레이스 진행 관리.
  - 각 라운드에서 Cars를 이동시키고, 시도 횟수와 게임 종료 상태를 관리한다.

- WinnerPolicy
  - 우승자를 결정하는 정책 객체.
  - Cars 상태를 기반으로 최대 위치를 가진 자동차를 찾아 반환한다.

- MoveStrategy (인터페이스)
  - 자동차 전진 조건을 추상화한 전략.

- RandomMoveStrategy
  - 랜덤 값 기반으로 이동 여부를 결정하는 구현체.

## 프로그래밍 요구 사항
- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
- 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- 3항 연산자를 쓰지 않는다.
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
